# AWS CDK Static Site v0.3.21

Version 0.3.21, tagged on 2026-09-20, strengthens regression coverage for the repository-local
Markdown checker without changing package behavior.

See the [changelog] for the release entry.

- [Highlights](#highlights)
- [Change Scope](#change-scope)
- [Compatibility and Configuration](#compatibility-and-configuration)
- [Support Boundary](#support-boundary)
- [Validation](#validation)
- [Deployment and Rollback](#deployment-and-rollback)
- [Known Limitations and Follow-Up](#known-limitations-and-follow-up)

## Highlights

- Verifies that a repository remains in scope when an ancestor directory is hidden.
- Verifies that Markdown under `.github` is checked while hidden caches, `cdk.out`, and
  `node_modules` remain excluded.
- Separates fenced-code behavior from directory-exclusion behavior so each contract fails clearly.

## Change Scope

The Markdown-checker unit suite now covers repository roots beneath hidden workspace directories,
explicit handling of `.github` documentation, each supported generated-directory exclusion, and
mixed fence markers inside code blocks. The checker implementation and command interface are
unchanged.

This release does not change package source, public exports, construct properties, construct IDs,
dependencies, synthesized CloudFormation behavior, workflows, AWS resources, or publication
mechanics.

## Compatibility and Configuration

No compatibility or configuration changes.

## Support Boundary

No support-boundary changes.

## Validation

- The focused Markdown-checker unit suite passes.
- The default unit and integration suite passes with 91 tests and 100% measured coverage.
- Formatting, linting, strict typing, dependency-boundary, Python-policy, Markdown-reference, and
  immutable-action-pin checks pass.
- The source distribution and wheel build successfully and pass `twine check`.
- The dated changelog section, release-document links, and whitespace checks pass.
- Hosted release-candidate and clean distribution-installation checks must still pass on the exact
  commit promoted for release.

## Deployment and Rollback

Merging this release does not deploy AWS resources. Creating the annotated `v0.3.21` tag runs the
existing release workflow, which must validate and publish the GitHub Release artifacts before the
release is considered complete. PyPI publication remains disabled.

No CloudFormation resource replacement, data migration, DNS change, service interruption, or cost
change is expected. If the additional tests prove unsuitable, revert their commit and prepare a new
patch release; package consumers can remain on `v0.3.20` because runtime behavior is unchanged.

## Known Limitations and Follow-Up

- External-link availability remains covered by the separate network-dependent documentation check.
- PyPI publication remains intentionally disabled pending a reviewed trusted-publishing workflow
  and protected environment.

See the [release archive] for related version records and the [release policy] for current release
gates.
