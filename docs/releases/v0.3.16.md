# AWS CDK Static Site v0.3.16 (Planned)

The planned version 0.3.16 strengthens release-documentation guardrails while preserving the
existing tag-triggered release and manual backfill behavior. No `v0.3.16` tag has been created yet.

## Highlights

- Requires release and hotfix pull requests to include a matching dated changelog section, versioned
  release document, and release-archive entry.
- Applies the same three-record requirement to tagged continuous delivery before build and
  publication work begins.
- Uses consistent `Verify release changelog` and `Verify versioned release document` step names in
  the continuous-integration and continuous-delivery workflows.
- Retains the existing workflow triggers, permissions, tag validation, manual backfill path, and
  release-publication behavior.

## Change Scope

The release and hotfix pull-request path in `.github/workflows/ci.yml` retains its focused changelog
check and adds a separate check for the versioned release document and archive entry. The tagged
release path in `.github/workflows/cd.yml` performs the same checks against the checked-out
immutable tag before running release tools or building artifacts. `CI-CD-WORKFLOWS.md` documents the
resulting three-record requirement.

The guardrails validate records committed to the pull-request branch or release tag; uncommitted
local files do not satisfy hosted automation. This release does not change package source, runtime
dependencies, public exports, construct configuration, synthesized CloudFormation behavior, AWS
resources, release triggers, or publication mechanics.

## Compatibility and Configuration

No consumer compatibility or configuration changes are required. Before opening a release or hotfix
pull request and before creating its tag, maintainers must commit a dated `CHANGELOG.md` section,
the matching `docs/releases/vX.Y.Z.md` document, and its `docs/releases/README.md` archive entry.

## Support Boundary

No Python, AWS CDK, package, stability, region, or infrastructure-support boundaries change in this
release.

## Validation

- GitHub Actions workflow syntax validation passes for the CI and CD workflows.
- The immutable GitHub Actions pin and Python-policy checks pass.
- Focused changelog-validator and command-line tests pass.
- Changelog validation passes for version 0.3.16.
- The versioned release document exists and is indexed by the release archive.
- Local Markdown-link validation and whitespace checks pass.
- Hosted release/hotfix pull-request and tagged continuous-delivery runs must still validate these
  guardrails on their respective GitHub runners.

## Deployment and Rollback

Merging this change does not deploy AWS resources. Creating the annotated `v0.3.16` tag runs the
existing release workflow, which verifies the committed release records before building artifacts
and documentation and publishing the GitHub Release.

If a guardrail incorrectly rejects a valid release record, correct the workflow through a reviewed
patch before creating the tag. Do not move or reuse an existing release tag. Package artifacts and
consumer infrastructure require no rollback because their behavior is unchanged.

## Known Limitations and Follow-Up

- Hosted automation can validate only release records present in the branch or immutable tag it
  checks out.
- The external-link documentation check remains network-dependent and advisory by default.
- PyPI publication remains intentionally disabled pending a reviewed trusted-publishing workflow and
  protected environment.
