# AWS CDK Static Site v0.3.24

Version 0.3.24 raises the minimum supported AWS CDK version and refreshes contributor-tool
requirements without changing the construct API or synthesized infrastructure behavior. No `v0.3.24`
tag has been created yet.

See the [changelog] for the release entry.

- [Highlights](#highlights)
- [Change Scope](#change-scope)
- [Compatibility and Configuration](#compatibility-and-configuration)
- [Support Boundary](#support-boundary)
- [Validation](#validation)
- [Deployment and Rollback](#deployment-and-rollback)
- [Known Limitations and Follow-Up](#known-limitations-and-follow-up)

## Highlights

- Raises the minimum supported `aws-cdk-lib` version from 2.269.0 to 2.271.0.
- Aligns the deterministic lowest-dependency constraint with package metadata.
- Refreshes minimum versions for development, documentation, and optional security tools.
- Aligns direct pre-commit execution with the project's development dependency floor.

## Change Scope

The package metadata now requires `aws-cdk-lib>=2.271.0,<3.0.0`, and `requirements/lowest.txt` pins
`aws-cdk-lib==2.271.0` for deterministic lower-bound testing.

Minimum contributor-tool versions are refreshed for Build, mypy, pre-commit, pytest, pytest-cov,
Ruff, Twine, Sphinx, the Read the Docs theme, and cdk-nag. The pre-commit configuration now requires
pre-commit 4.6.2, matching the development dependency declared in `pyproject.toml`.

This release does not change package source, public exports, construct properties, construct IDs,
synthesized CloudFormation behavior, workflows, AWS resources, release artifacts, or publication
mechanics.

## Compatibility and Configuration

Consumers must use `aws-cdk-lib` 2.271.0 or newer within the supported 2.x series. Consumers already
using a compatible version require no configuration or code changes. Contributors should reinstall
the development environment so the refreshed minimum tool versions are resolved.

## Support Boundary

The minimum supported `aws-cdk-lib` version changes from 2.269.0 to 2.271.0. The supported Python,
Constructs, AWS service, region, and infrastructure boundaries remain unchanged.

## Validation

- Popo's dependency-policy check confirms that the lowest-runtime constraint matches package
  metadata.
- Ruff formatting and linting pass.
- Strict mypy checks pass for the package and tests.
- The unit suite passes with 100% measured coverage, and the integration suite passes.
- Strict Sphinx documentation, distribution metadata, and pre-commit configuration checks pass.
- The dependency-boundary matrix must pass with `aws-cdk-lib==2.271.0` on Python 3.13 and 3.14.
- Hosted release-candidate, distribution, and clean-installation checks must still pass on the exact
  commit promoted for release.

## Deployment and Rollback

Merging this release does not deploy AWS resources. Creating the annotated `v0.3.24` tag runs the
existing release workflow, which must validate and publish the GitHub Release artifacts before the
release is considered complete. PyPI publication remains disabled.

No CloudFormation resource replacement, data migration, DNS change, service interruption, or cost
change is expected. Consumers pinned below `aws-cdk-lib` 2.271.0 must update that dependency before
installing this release. If the dependency-floor changes cause an unforeseen regression, restore the
affected requirements in a corrective patch; package consumers can remain on `v0.3.23` while the
issue is resolved.

## Known Limitations and Follow-Up

- External-link availability remains covered by the separate network-dependent documentation check.
- PyPI publication remains intentionally disabled pending a reviewed trusted-publishing workflow and
  protected environment.

See the [release archive] for related version records and the [release policy] for current release
gates.
