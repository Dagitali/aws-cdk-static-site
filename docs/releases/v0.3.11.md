# AWS CDK Static Site v0.3.11

Version 0.3.11 updates the GitHub Action that obtains short-lived AWS credentials for the manual,
disposable deployment test.

## Highlights

- Updates `aws-actions/configure-aws-credentials` from 6.2.3 to 6.2.4 through [Dependabot pull
  request 5].
- Retains the action's immutable commit pin, changing it from
  `e6de054238d6b7531b4efff3b6587d9aade6a06c` to
  `cbe3b392738ccf3f987d68400dafcf4b0624a56c`.
- Incorporates upstream fixes for account-ID handling, proxy-secret masking in logs, and avoiding
  backoff sleep after the final retry attempt.

## Change Scope

This release changes only the `aws-actions/configure-aws-credentials` reference in
`.github/workflows/deployment-test.yml`. The workflow remains manually dispatched from `main`,
requires the protected `deployment-test` environment and explicit `DEPLOY-AND-DESTROY`
confirmation, and continues to use GitHub OIDC for short-lived credentials.

Workflow triggers, permissions, inputs, role configuration, allowed-account enforcement, account-ID
masking, synthesis, resource allowlisting, deployment verification, and cleanup behavior remain
unchanged. The package source, public API, runtime dependencies, examples, and synthesized AWS
infrastructure are also unchanged.

## Compatibility and Configuration

No compatibility or configuration changes are required. Existing `AWS_ACCOUNT_ID` and
`AWS_DEPLOY_TEST_ROLE_ARN` environment variables and the deployment-test role trust policy remain
valid.

## Support Boundary

No Python, AWS CDK, browser, stability, or package-support boundaries change in this release.

## Validation

- The workflow-pin policy accepts the new immutable commit reference and its 6.2.4 annotation.
- Targeted pre-commit checks pass for the changed workflow, changelog, and release document.
- `make check` passes with repository policy checks, Ruff, mypy, 65 unit and integration tests,
  100% measured coverage, distribution builds, and `twine check`.
- The release pull request's required GitHub Actions checks must pass for the exact revision.
- Because unit tests do not assume AWS credentials or create deployed resources, the credential
  step requires a reviewed manual deployment test when deployment-level confirmation is needed.

## Deployment and Rollback

Promoting and tagging this release does not run the disposable deployment test; the workflow has
only a manual trigger. The next approved deployment-test run will use version 6.2.4 of the
credential action while retaining the existing bounded stack and mandatory cleanup controls.

No AWS resource replacement, DNS change, package migration, or service interruption is expected.
Before a manual run, retain the environment approval and verify that the synthesized template stays
within the documented resource allowlist. After the run, confirm CloudFormation reports deletion of
the exact `AwsCdkStaticSiteTest-<run-id>` stack.

If the updated action causes a workflow regression, restore the prior immutable 6.2.3 commit pin
through the normal reviewed hotfix process. Any stack left by an interrupted run must still be
handled through the documented exact-name cleanup procedure; reverting the workflow does not remove
deployed resources.

## Known Limitations and Follow-Up

- Local validation cannot exercise GitHub's OIDC token issuance, protected-environment approval, or
  the configured AWS role.
- GitHub-hosted confirmation of the credential action and end-to-end cleanup remains required on an
  approved manual run when deployment-level assurance is needed.
