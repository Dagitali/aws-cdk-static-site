# AWS CDK Static Site v0.3.26

Version 0.3.26, tagged on 2026-09-27, is planned to update the AWS credentials action used by the
manual disposable deployment test. This is an untagged release candidate, prepared on 2026-09-27.

See the [changelog] for the release entry.

- [Highlights](#highlights)
- [Change Scope](#change-scope)
- [Compatibility and Configuration](#compatibility-and-configuration)
- [Support Boundary](#support-boundary)
- [Validation](#validation)
- [Deployment and Rollback](#deployment-and-rollback)
- [Known Limitations and Follow-Up](#known-limitations-and-follow-up)

## Highlights

- Updates `aws-actions/configure-aws-credentials` from v6.2.4 to v6.3.0.
- Retains an immutable full-commit-SHA pin for the action.
- Preserves the manual deployment test's existing authorization and cleanup controls.

## Change Scope

[Pull request #8] changes one action reference in `.github/workflows/deployment-test.yml` from
`cbe3b392738ccf3f987d68400dafcf4b0624a56c` (v6.2.4) to `e1253824e5c10ff9df46874f81ed3ec929e19cfd`
(v6.3.0). This is the complete implementation diff since v0.3.25; this candidate additionally
supplies its changelog, release record, and archive entry.

The action still obtains short-lived AWS credentials through GitHub OIDC. Its configured role,
session name, region, allowed-account check, and account-ID masking inputs are unchanged. The
workflow remains manual, restricted to `main`, and requires the `DEPLOY-AND-DESTROY` confirmation
and `deployment-test` environment. Resource allowlisting and cleanup behavior are unchanged.

## Compatibility and Configuration

No consumer migration or configuration change is required. Package source, construct API,
synthesized resources, and Python dependency bounds are unchanged. The update affects the
credentials action implementation used when an operator runs the manual deployment test.

## Support Boundary

Python and AWS CDK support, service and region boundaries, and consumer responsibilities remain
unchanged. Normal CI remains credential-free and deployment-free; this update does not broaden
workflow permissions or enable automatic AWS deployments.

## Validation

Preparation baseline: merge commit `5d716d9037b03ed0a9e098c7b6a8c3d18c0e7a2f` from [pull request
#8], plus this release-documentation update. The final release commit and tag are not yet
established.

`make github-actions-pins python-policy docs-markdown release-changelog RELEASE_VERSION=0.3.26` and
`git diff --check` passed during preparation. `make docs-strict` failed before Sphinx ran: pip could
not uninstall the existing local `aws-cdk-static-site` installation, which reported version `None`
and lacked a `RECORD` file. Repair that environment and rerun strict documentation validation before
release.

The live deployment workflow is not run as part of release-note preparation. Static checks cannot
establish successful OIDC authentication or deployment with the updated action; any live test
requires separate operator authorization.

Complete the package, distribution, clean-installation, and hosted gates in the [release checklist]
against the final candidate before declaring release readiness.

## Deployment and Rollback

Merging this update does not deploy AWS resources. An explicitly authorized run of the manual test
continues to create and clean up its bounded stack under the existing safeguards. Tagging and GitHub
publication follow the [release policy]; PyPI publication remains disabled.

If the updated action causes a workflow regression, restore the previous reviewed full-SHA pin in a
corrective commit and release, then revalidate. Preserve existing tags. Package consumers can remain
on v0.3.25 while maintainers investigate because the construct implementation is unchanged.

## Known Limitations and Follow-Up

- Record the final candidate commit and completed release-gate results before claiming completion.
- Strict documentation validation remains blocked by the local installation-metadata issue above.
- The action update has not been exercised against AWS during this documentation task.
- Local validation does not establish hosted deployment or publication outcomes.

See the [release archive] for related version records and the [release policy] for current release
gates.
