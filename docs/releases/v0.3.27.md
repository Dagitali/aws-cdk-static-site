# AWS CDK Static Site v0.3.27

Version 0.3.27, tagged on 2026-09-27, refreshes the Commitizen and Ruff pre-commit hooks.

See the [changelog] for the release entry.

- [Highlights](#highlights)
- [Change Scope](#change-scope)
- [Compatibility and Configuration](#compatibility-and-configuration)
- [Support Boundary](#support-boundary)
- [Validation](#validation)
- [Deployment and Rollback](#deployment-and-rollback)
- [Known Limitations and Follow-Up](#known-limitations-and-follow-up)

## Highlights

- Updates the Commitizen hook from v4.18.0 to v4.18.1.
- Updates the Ruff hook revision from v0.16.7 to v0.16.8.
- Preserves existing hook selection, arguments, and execution stages.

## Change Scope

[Pull request #9] changes two `rev` values in `.pre-commit-config.yaml`: the Commitizen and
`ruff-pre-commit` repositories. This is the complete implementation diff since v0.3.26. This
candidate also adds its changelog entry, release document, and archive link.

Commitizen continues to run at the commit-message stage, and the configured Ruff lint hook retains
its existing behavior settings. Package code, tests, GitHub Actions workflows, and dependency
requirements in `pyproject.toml` are unchanged.

## Compatibility and Configuration

Package consumers require no migration or configuration changes. Contributors running the configured
hooks receive the updated revisions through pre-commit's managed hook environments. Hook revisions
are separate from the project environment's development-tool dependency requirements; this release
does not change the Ruff minimum declared in `pyproject.toml`.

## Support Boundary

Python and AWS CDK support, runtime dependencies, public construct interfaces, synthesized
resources, and AWS operational responsibilities remain unchanged. The changes affect contributor
tooling.

## Validation

Preparation baseline: merge commit `d0c8e5c4b212e1e4a4503b9b645c53335d2f23d1` from [pull request
#9], plus this release-documentation update. The final release commit and tag are not yet
established.

Pre-commit configuration validation, `make docs-markdown`, `make release-changelog
RELEASE_VERSION=0.3.27`, and `git diff --check` passed during preparation. `make docs-strict` failed
before Sphinx ran because pip could not uninstall the existing local package: its version was `None`
and its `RECORD` file was missing. Repair that environment and rerun the strict documentation check.
Configuration validation does not prove execution of the updated hooks. Runtime tests and hook
installation are not part of this documentation preparation; complete applicable checks from the
[release checklist] against the final candidate before declaring release readiness.

## Deployment and Rollback

Merging these hook updates does not deploy AWS resources or require a data migration, DNS change, or
resource replacement. Tagging and publication follow the [release policy]; PyPI publication remains
disabled.

If an updated hook causes a contributor-workflow regression, restore its previous reviewed revision
in a corrective commit and release, then rerun the affected checks. Preserve existing tags. Package
consumers can remain on v0.3.26 because construct behavior is unchanged.

## Known Limitations and Follow-Up

- Record the final release commit and completed checks before claiming release completion.
- Strict documentation validation remains blocked by the local installation-metadata issue above.
- Local configuration and documentation checks do not establish hosted or hook-execution results.
- External-link availability remains covered by the separate network-dependent documentation check.

See the [release archive] for related version records and the [release policy] for current release
gates.
