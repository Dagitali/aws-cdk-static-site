# AWS CDK Static Site v0.3.18 (Planned)

The planned version 0.3.18 raises the package's minimum supported `aws-cdk-lib` version to 2.269.0
and keeps lowest-dependency testing aligned with that published compatibility boundary. No
`v0.3.18` tag has been created yet.

## Highlights

- Raises the minimum supported `aws-cdk-lib` version from 2.267.0 to 2.269.0.
- Aligns the deterministic lowest-dependency constraint with the package metadata so compatibility
  checks exercise the published minimum.

## Change Scope

The package metadata now requires `aws-cdk-lib>=2.269.0,<3.0.0`, and
`requirements/lowest.txt` pins `aws-cdk-lib==2.269.0` for the lowest-dependency test matrix. The
`constructs` dependency bounds remain unchanged.

This release does not change package source, public exports, construct configuration, construct
IDs, synthesized CloudFormation behavior, AWS resources, workflow permissions, release triggers,
or publication mechanics. The dependency update was introduced by [pull request #4].

## Compatibility and Configuration

Consumers must use `aws-cdk-lib` 2.269.0 or newer within the supported 2.x series. Consumers already
using 2.269.0 or a later compatible 2.x release require no configuration or code changes. A resolver
that still pins 2.267.0 or 2.268.0 must update that pin before installing this release.

## Support Boundary

The minimum supported `aws-cdk-lib` version changes from 2.267.0 to 2.269.0. The supported Python
versions, `constructs` range, package stability level, AWS services, regions, and infrastructure
operating assumptions remain unchanged.

## Validation

- Pull-request testing passes on Python 3.13 and 3.14 with the 2.269.0 lowest-dependency constraint.
- Pull-request testing passes on Python 3.13 and 3.14 with the newest dependencies permitted by
  package metadata.
- macOS and Windows installation smoke tests pass.
- Distribution validation passes.
- The package dependency-boundary check must pass after the canonical lower bound and lowest
  constraint are aligned.
- The full release-candidate checks, synthesis review, changelog validation, and artifact validation
  must still pass before tagging.

## Deployment and Rollback

Merging this release does not deploy AWS resources. Creating the annotated `v0.3.18` tag runs the
existing release workflow, which must validate and publish the GitHub Release artifacts before the
release is considered complete. PyPI publication remains disabled.

No CloudFormation resource replacement, data migration, service interruption, or cost change is
expected because construct source and synthesized behavior are unchanged. If the raised dependency
boundary causes a consumer compatibility problem, correct it with a new patch release rather than
moving or reusing the published tag. Consumers can remain on `v0.3.17` while the issue is resolved.

## Known Limitations and Follow-Up

- Consumers pinning an older `aws-cdk-lib` release must update their dependency declaration before
  adopting this package version.
- The GitHub-hosted release-candidate and tagged-release checks remain required on the exact commits
  promoted through the release workflow.
