# AWS CDK Static Site v0.3.23

Version 0.3.23 removes unused test-support plumbing and strengthens local validation without
changing package or infrastructure behavior. No `v0.3.23` tag has been created yet.

- [Highlights](#highlights)
- [Change Scope](#change-scope)
- [Compatibility and Configuration](#compatibility-and-configuration)
- [Support Boundary](#support-boundary)
- [Validation](#validation)
- [Deployment and Rollback](#deployment-and-rollback)
- [Known Limitations and Follow-Up](#known-limitations-and-follow-up)

## Highlights

- Removes the unused `write_file` pytest fixture and its `FileWriter` support type.
- Removes testing guidance that referenced the retired fixture.
- Expands content-path validation coverage to include missing paths and existing files.
- Ensures the release-changelog Make target uses the project environment's pinned Popo installation.
- Adds a Make contract test that distinguishes the project interpreter from the bootstrap
  interpreter.
- Keeps the remaining repository, package, construct, and Popo consumer contracts unchanged.

## Change Scope

The direct tests for the deprecated local policy implementation were removed in `v0.3.22`, leaving
their shared temporary-file fixture unused. This release deletes that fixture from
`tests/conftest.py`, removes `tests/support/files.py`, and synchronizes the testing guide with the
remaining support surface.

The construct unit test now verifies that content deployment rejects both a missing path and a path
identifying a file instead of a directory. This broadens coverage of the existing validation without
changing the validation itself.

The `release-changelog` Make target now invokes Popo through the same project-environment Python
interpreter as the other repository-policy targets. Its regression test prevents the target from
falling back to the bootstrap interpreter, where pinned development tools may not be installed.

No test module or active test case is removed. This release does not change package source, public
exports, construct properties, construct IDs, runtime or development dependencies, synthesized
CloudFormation behavior, workflows, AWS resources, release artifacts, or publication mechanics.

## Deployment and Rollback

Merging this release does not deploy AWS resources. Creating the annotated `v0.3.23` tag runs the
existing release workflow, which must validate and publish the GitHub Release artifacts before the
release is considered complete. PyPI publication remains disabled.

No CloudFormation resource replacement, data migration, DNS change, service interruption, or cost
change is expected. If the fixture removal or local quality-gate changes cause an unforeseen
contributor-workflow regression, restore the affected test support or Make invocation in a
corrective patch; package consumers can remain on `v0.3.22` because runtime behavior is unchanged.

## Known Limitations and Follow-Up

- External-link availability remains covered by the separate network-dependent documentation check.
- PyPI publication remains intentionally disabled pending a reviewed trusted-publishing workflow and
  protected environment.
