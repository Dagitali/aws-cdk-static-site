# AWS CDK Static Site v0.3.17 (Planned)

The planned version 0.3.17 standardizes Python project setup and quality gates across local and
hosted automation. No `v0.3.17` tag has been created yet.

## Highlights

- Introduces `.github/actions/setup-python-project/action.yml` to centralize cached Python setup,
  optional project installation, dependency extras, editable-install selection, `pip check`, and
  environment-version reporting.
- Reuses the composite action in current-branch CI, security, and deployment-test jobs while keeping
  tagged-release jobs self-contained for historical tag backfills.
- Makes `make check-pre-push` the hosted CI quality gate and adds discoverable `format-check`,
  `synth`, `docs-check`, and `ci` Make targets.
- Extends immutable GitHub Actions reference validation recursively across workflows and composite
  actions under the canonical `github-actions-pins` name.

## Change Scope

The CI workflow now uses the local composite action for project setup and delegates its main quality
gate to the same `make check-pre-push` target available to contributors. Documentation, dependency-
matrix, installation-smoke, security, and disposable-deployment jobs use the same setup abstraction
where their checked-out branch is authoritative. Release automation remains self-contained because
a historical backfill can check out a tag created before the local action existed.

The Make interface adds non-mutating format validation, explicit example synthesis, deterministic
strict HTML and EPUB documentation validation, and a local CI alias. The GitHub Actions pin checker
now scans both `.github/workflows/` and `.github/actions/`, and its hook, CLI command, module, tests,
and primary Make target use `github-actions-pins` terminology. The former `workflow-pins` Make target
and `check-workflow-pins` CLI command remain temporarily available with deprecation warnings.

Contributor, testing, CI/CD, agent, troubleshooting, and change-impact documentation now describe
the shared setup action and aligned quality gates. This release does not change package source,
runtime dependencies, public exports, construct configuration, synthesized CloudFormation behavior,
AWS resources, workflow permissions, release triggers, or publication mechanics.

## Compatibility and Configuration

No consumer compatibility or configuration changes are required. Contributors and automation should
use `make github-actions-pins` or `python -m scripts check-github-actions-pins`; the former names
continue to work during the deprecation period.

The composite action requires callers to check out the repository first. Its `install` and
`editable` inputs are string booleans, and dependency extras are supplied as a comma-separated
string.

## Support Boundary

No Python, AWS CDK, package, stability, region, or infrastructure-support boundaries change in this
release. The composite action is repository-local automation rather than a separately versioned
public action.

## Validation

- GitHub Actions workflow syntax validation passes for the affected workflows.
- The canonical GitHub Actions pin check covers both workflow and composite-action YAML and passes.
- The Python-version policy check passes.
- Focused pin-validator and command-line tests pass, including legacy-alias deprecation behavior.
- The composite action metadata parses as YAML and declares a composite run type.
- Changelog validation passes for version 0.3.17.
- The versioned release document exists and is indexed by the release archive.
- Whitespace validation passes.
- Hosted CI, security, and deployment-test jobs must still validate the shared action on their
  respective GitHub runners.

## Deployment and Rollback

Merging this change does not deploy AWS resources. Creating the annotated `v0.3.17` tag runs the
existing release workflow, which remains independent of the new branch-local composite action and
must complete its existing validation before publishing the GitHub Release.

If the shared action causes a hosted current-branch workflow regression, restore the affected job's
explicit setup and installation steps through a reviewed patch. No package artifact or consumer
infrastructure rollback is required because runtime and synthesized behavior are unchanged.

## Known Limitations and Follow-Up

- The deprecated `workflow-pins` Make target and `check-workflow-pins` CLI alias are retained for
  this patch release and may be removed in a future minor release.
- Historical tagged-release jobs intentionally do not use the repository-local composite action.
- The external-link documentation check remains network-dependent and advisory by default.
- PyPI publication remains intentionally disabled pending a reviewed trusted-publishing workflow and
  protected environment.
