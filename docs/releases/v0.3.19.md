# AWS CDK Static Site v0.3.19 (Planned)

The planned version 0.3.19 strengthens repository maintenance, contributor guidance, and release
evidence without changing the package API or synthesized infrastructure. No `v0.3.19` tag has been
created yet.

## Highlights

- Adds deterministic repository-wide validation for relative Markdown links and generated heading
  anchors through the shared maintenance CLI, Make quality gate, and pre-commit configuration.
- Rejects invalid boolean inputs to the shared Python setup action before environment setup and adds
  direct unit coverage for reusable script helpers.
- Adds a package-specific onboarding guide and aligns contribution, agent, review, security,
  architecture-decision, and release guidance around explicit evidence and ownership boundaries.
- Documents the construct's existing security controls, consumer responsibilities, and deliberate
  exclusions in the public security policy.

## Change Scope

The new Markdown validator checks maintained Markdown files for unresolved relative links,
fragments, and duplicate or missing generated heading anchors without requiring network access. It
is exposed through `python -m scripts`, `make docs-markdown`, the broader Make quality gate, and
pre-commit. The validator includes focused tests, and a stale Learnings table-of-contents anchor was
corrected as its first repository finding.

The repository-local Python setup action now accepts only explicit `true` or `false` values for its
`install` and `editable` inputs and fails before Python or dependency setup when either input is
invalid. Direct tests now protect common script-support behavior in addition to the command-line
contracts.

Maintainer documentation now supplies a single onboarding path and more consistent expectations for
privacy, accessibility, confidential evidence, deployment authorization, architecture-decision
metadata, release validation, and rollback evidence. The expanded security policy records controls
already enforced by the construct and identifies WAF, monitoring, account governance, application
security, and destructive data-lifecycle choices as consumer-owned concerns.

This release does not change package source, public exports, construct properties, construct IDs,
runtime dependencies, synthesized CloudFormation behavior, AWS resources, workflow permissions,
release triggers, or publication mechanics.

## Compatibility and Configuration

No consumer compatibility or configuration changes.

Contributors gain the `make docs-markdown` target. Existing `make check` and pre-commit workflows
invoke the new deterministic validation automatically. Composite-action callers already using valid
boolean inputs require no changes; callers passing another spelling now receive an immediate error.

## Support Boundary

No Python, AWS CDK, package, stability, service, region, or infrastructure-support boundaries
change in this release. The documented security ownership model clarifies the existing boundary; it
does not add a certification or transfer consumer responsibilities to the construct.

## Validation

- The Markdown link and heading-anchor check passes across the maintained repository documentation.
- Strict Sphinx HTML and EPUB documentation builds pass.
- The default unit and integration suite passes with 80 tests and 100% measured coverage.
- Focused tests cover valid and invalid Markdown references, command-line dispatch, and reusable
  script helpers.
- Formatting, linting, strict typing, dependency-boundary, Python-policy, and immutable-action-pin
  checks pass.
- The source distribution and wheel build successfully and pass `twine check`.
- Whitespace validation passes.
- Clean distribution-installation smoke tests, synthesis review, release-archive inspection, and
  hosted release-candidate checks must still pass on the exact commit promoted for release.

## Deployment and Rollback

Merging this release does not deploy AWS resources. Creating the annotated `v0.3.19` tag runs the
existing release workflow, which must validate and publish the GitHub Release artifacts before the
release is considered complete. PyPI publication remains disabled.

No CloudFormation resource replacement, data migration, DNS change, service interruption, or cost
change is expected because construct source and synthesized behavior are unchanged. If the new
repository checks disrupt contributor automation, correct them with a reviewed patch release;
consumers can remain on `v0.3.18` while that correction is prepared.

## Known Limitations and Follow-Up

- The Markdown validator intentionally checks repository-local references only; external URL
  availability remains covered by the separate network-dependent documentation check.
- GitHub-hosted release-candidate checks remain required on the exact commit promoted through the
  release workflow.
- PyPI publication remains intentionally disabled pending a reviewed trusted-publishing workflow
  and protected environment.
