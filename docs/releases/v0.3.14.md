# AWS CDK Static Site v0.3.14 (Planned)

The planned version 0.3.14 corrects strict EPUB documentation validation in hosted CI and release
automation. No `v0.3.14` tag has been created yet.

## Highlights

- Prevents Sphinx EPUB builds from treating internal doctree files as files to package.
- Applies the correction consistently to pull-request CI and tagged-release documentation checks.
- Retains strict warning-as-error behavior instead of suppressing valid EPUB warnings.

## Change Scope

The documentation commands in `.github/workflows/ci.yml` and `.github/workflows/cd.yml` now pass a
builder-specific directory through Sphinx's `-d` option. Doctrees are written under
`docs/build/doctrees/<builder>` rather than inside `docs/build/<builder>`.

Previously, the EPUB builder discovered its own `.doctree` and `environment.pickle` files beneath
the output directory and reported `epub.unknown_project_files` warnings. Because hosted automation
uses `-W`, those warnings correctly failed the job. Separating build state from generated output
matches the established local Make targets and removes the false packaging warnings.

This release does not change package source, runtime dependencies, public exports, construct
configuration, synthesized CloudFormation behavior, or AWS resources.

## Compatibility and Configuration

No consumer compatibility or configuration changes are required. Maintainers do not need to weaken
Sphinx warning handling or add warning suppressions.

## Support Boundary

No Python, AWS CDK, package, stability, or infrastructure-support boundaries change in this
release.

## Validation

- `actionlint .github/workflows/*.yml` passes.
- The immutable GitHub Actions pin check passes.
- The strict local EPUB build passes with doctrees outside the EPUB output directory.
- Changelog validation passes for version 0.3.14.
- Hosted CI and tagged-release documentation jobs must still validate the corrected commands on
  their respective GitHub runners.

## Deployment and Rollback

Merging this change does not deploy AWS resources. Creating the annotated `v0.3.14` tag runs the
existing release workflow, which must complete its package, SBOM, checksum, and documentation
validation before publishing the GitHub Release.

If the directory separation causes an unexpected documentation regression, restore the previous
commands through a reviewed hotfix while retaining strict warning handling. Package artifacts and
consumer infrastructure require no rollback because their behavior is unchanged.

## Known Limitations and Follow-Up

- The external-link documentation check remains network-dependent and advisory by default.
- PyPI publication remains intentionally disabled pending a reviewed trusted-publishing workflow and
  protected environment.
