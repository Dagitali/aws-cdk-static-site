# AWS CDK Static Site v0.3.15 (Planned)

The planned version 0.3.15 establishes a maintainable, evidence-backed documentation system for the
reusable construct and its repository operations. No `v0.3.15` tag has been created yet.

## Highlights

- Adds authoritative root documentation for architecture, design, roadmap, reusable learnings, and
  automated-agent conventions.
- Organizes detailed guidance into indexed API, architecture, decision, development, playbook,
  runbook, tutorial, and release sections.
- Connects configuration references to repeatable procedures for consumer adoption, required-check
  maintenance, deployment validation, incident response, releases, and first-site synthesis.
- Preserves the completed construct-extraction record as architecture history while retaining one
  active roadmap.

## Change Scope

This release adds and expands Markdown documentation throughout the repository. New materials cover
public API evolution, change-impact review, architectural decisions, documentation synchronization,
agent workflows, consumer-project scaffolding, incident response, and introductory synthesis. The
existing adoption, deployment-testing, release, maintainer, and branch-protection guidance is
organized around clearer playbook, runbook, and authoritative-reference boundaries.

Repository navigation now links the root guides, documentation indexes, release archive, and related
operational material. The release checklist and maintainer runbooks were moved into their
corresponding documentation sections without intentionally changing their operational meaning.

This release does not change Python package source, public exports, dependencies, construct
configuration, synthesized CloudFormation behavior, workflow execution, or AWS resources.

## Compatibility and Configuration

No consumer compatibility or configuration changes are required. Existing consumers can continue
using the same construct properties and deployment configuration.

Some documentation paths changed as runbooks and playbooks were classified by purpose. Repository
links and indexes have been updated to point to their new locations.

## Support Boundary

No Python, AWS CDK, package, region, stability, or infrastructure-support boundaries change in this
release. The new documents clarify existing ownership and operational boundaries; they do not expand
the construct's public contract.

## Validation

- `git diff --check` passes.
- A repository-wide local-target check passes across 82 maintained Markdown files and confirms that
  all 32 versioned release-note documents are indexed.
- `make docs-strict` completes without Sphinx warnings.
- `make release-changelog RELEASE_VERSION=0.3.15` confirms that the dated changelog entry is ready
  for release.
- Required hosted checks must still pass on the release pull request before the tag is created.

## Deployment and Rollback

Merging these documentation changes does not deploy or modify AWS resources. Creating the annotated
`v0.3.15` tag from the authoritative merged `main` commit runs the existing release workflow, which
must validate the package, SBOM, checksums, and documentation before publishing the GitHub Release.

If a moved document or link is incorrect, correct it through a reviewed patch. Package artifacts and
consumer infrastructure require no rollback because their behavior is unchanged.

## Known Limitations and Follow-Up

- First-consumer adoption is in progress and may reveal additional documentation refinements.
- The external-link documentation check remains network-dependent and advisory by default.
- PyPI publication remains intentionally disabled pending a reviewed trusted-publishing workflow and
  protected environment.
